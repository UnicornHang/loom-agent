# 多 Agent 热点内容创作平台｜产品需求文档（PRD）

> 版本：V1.0（落地方案）  
> 日期：2026-11-15  
> 定位：面向企业内容运营团队，把高表现种草作品发现、产品匹配、内容创作、人工审校和成果管理串成可追溯的工作流。首批业务为 3C 电子产品，行业与品类可配置。

## 1. 产品目标与边界

### 1.1 核心目标

1. 按当前启用的行业、产品品类、具体商品和内容方向，持续发现**有明确热度证据的种草图文、测评文章和种草视频**，并集中呈现在内容灵感大厅。首批行业为 3C 全品类；泛社会话题或娱乐热搜不属于默认候选。
2. 让运营人员从热点或自带素材发起创作，经过关键节点确认，产出可保存、可导出的图文或视频。
3. 让 AI 负责检索、分析、推荐和制作，用户保留产品选择、内容定稿及发布决定权。
4. 保留每次工作流的输入、版本、操作和结果，便于复盘与追责。

### 1.2 本期范围

- 热点订阅、定时采集、去重、分类、检索和失效标记。
- 产品库及按用户权限过滤的产品推荐。
- 图文、纯文字、视频三条创作路径；支持段落或镜头级局部修改、手工编辑和版本记录。
- 可配置的 Agent、模型连接、提示词版本和工作流日志。
- 成果库中的保存、检索、预览与导出。

### 1.3 后续范围

- 第三方平台一键发布、发布排期与效果回收。
- 多人协作审批、品牌知识库、A/B 测试和基于转化数据的推荐优化。
- 更复杂的视频真人拍摄、口型同步及跨平台自动改写。

首期交付是**保存到内容库与下载文件**；实际向外部平台发布在后续版本接入。内容库可以记录“创作者已确认”，但不把它等同于平台已发布或审核已通过。

## 2. 用户与权限

| 角色 | 主要职责 | 默认权限 |
| --- | --- | --- |
| 平台管理员 | 管理租户、成员、模型、密钥、采集源和全局策略 | 全量配置与审计 |
| 产品管理员 | 维护产品资料及可见范围 | 管理授权范围内产品 |
| 内容运营 | 选择热点、匹配产品、创作、编辑、保存与导出 | 使用获授权的热点和产品 |
| 审核人员 | 查看待审内容、运行或复核审核、记录结论 | 查看被分配的工作流 |
| 只读成员 | 浏览授权成果与日志 | 只读 |

权限以租户为第一层隔离，再按产品分组或产品 ID 授权。**产品推荐、搜索、详情、图片预览、日志和导出都必须在服务端执行同一权限过滤**；不得仅在界面隐藏。无权产品不进入模型上下文，也不出现在推荐分数说明中。平台管理员可配置角色，产品管理员不可自行扩大授权范围。

## 3. 信息架构

1. **热点大厅（内容灵感大厅）**：3C 种草作品订阅筛选、作品列表、热度依据、详情、收藏、发起工作流。
2. **工作流入口**：聊天式输入，可粘贴链接、上传素材、描述创作目标；展示节点卡片、待确认操作和进度。
3. **我的工作流**：进行中、待我处理、已完成、失败；支持从可恢复节点继续。
4. **内容创作**：图文和视频成果库，支持版本、预览、下载及状态筛选。
5. **产品库**：产品资料、图片、标签、品牌约束、授权范围和上下架状态。
6. **Agent 配置**：模型连接、任务路由、提示词、参数、测试与版本发布。
7. **工作流日志**：每次执行的事件时间线、模型/提示词版本、人工选择、失败原因与成本。
8. **管理设置**：用户、角色、热点源、采集计划、配额和审核规则。

## 4. 端到端流程与路由规则

### 4.1 入口与素材判断

热点大厅点击“用此热点创作”，或在聊天式入口提交链接、文字、图片、视频。系统先保存原始输入和来源信息，再提取文本、图片元数据、视频转写与关键帧。提取失败时提示用户补充可读素材；不得根据无法读取的链接编造内容。

分析 Agent 输出结构化结果：`内容类型`（纯文字 / 带图图文 / 视频）、`主题摘要`、`是否出现商品或品牌`、`商品线索`、`置信度`、`来源与权利提示`。低置信度或类型混合时由用户确认类型。用户可以更正分析结果，更正会写入日志。

| 输入类型 | 产品步骤 | 创作与制作步骤 |
| --- | --- | --- |
| 纯文字热点 | 跳过 | 文章 Agent → 编辑确认 → 审核 → 保存/导出 |
| 带图图文，含产品线索 | 推荐并由用户选择产品 | 文章 Agent → 美工 Agent → 复核 → 审核 → 保存/导出 |
| 带图图文，无产品线索 | 默认跳过；用户可主动关联产品 | 文章 Agent → 按需美工 Agent → 复核 → 审核 → 保存/导出 |
| 视频热点 | 若有产品线索则推荐；否则允许“无产品创作”或主动关联 | 首期：编剧 Agent → 分镜师 Agent → 保存/下载剧本与分镜；P1 增加视频生成与成片复核 |

“纯文字热点”保持无产品、无美工的轻流程。视频和带图图文允许无产品创作，以免无匹配商品时流程卡死；用户主动关联产品后，后续 Agent 才能使用该产品资料。对外呈现时必须清楚区分热点原内容、公司产品信息与 AI 新生成内容。

### 4.2 工作流状态

统一主状态：`草稿` → `分析中` → `待类型确认/待产品选择` → `生成中` → `待内容确认` → `制作中` → `待最终确认` → `已保存/已下载`。AI 审核是从待最终确认或已保存成果发起的可选支路：`审核中` → `审核通过/发现问题/需人工复核`。任一步骤可进入 `失败待重试`、`已取消`。节点完成后记录输入版本与输出版本；重做只影响当前节点及其下游，不覆盖既有版本。

每个长任务必须显示进度、排队状态、取消入口和失败原因。刷新或断线后可从已持久化节点继续。用户确认是不可由 Agent 自动跳过的门槛。

**所有 Agent 的执行过程对用户可见并可回看。**每个 Agent 页面展示：当前阶段、正在处理的任务、已使用的素材与产品依据、实际调用的工具及结果摘要、产生的草稿/图片/镜头版本、自检与修订摘要、失败或待用户补充事项。实时更新，刷新后保留时间线。展示的是可验证的工作记录和决策摘要，不展示或伪造模型内部原始推理；无权产品、密钥和其他敏感信息不得出现在过程记录中。

## 5. 功能需求

### 5.1 热点获取 Agent 与热点大厅

这里的“热点”指**具体的高表现内容作品**，例如一篇热门耳机测评图文或一条高互动的充电宝种草视频，不是单独的热搜关键词。用户可创建多个订阅：行业、品类、品牌/型号、使用场景、种草内容类型（开箱、测评、横评、教程、清单等）、包含词、排除词、平台/来源、地区、语言、图文/视频、采集频率。首批 3C 行业默认启用**全品类**，由管理员维护可增删的品类树，不把几个示例词当成唯一范围。后台任务全天运行，按每个来源允许的方式和频率定时采集；“24 小时不间断”指持续调度与故障恢复，不承诺每分钟都有新作品。源不可用时记录失败、重试并告警，不生成虚构热点。

采集流水线为 `来源候选 → 作品级去重 → 当前行业与品类相关性判断 → 种草/测评意图判断 → 热度证据校验 → 权利与可访问状态检查 → 入大厅`。品类或意图置信度低的作品进入待人工复核队列，不自动进入推荐列表。宁可显示“今日符合条件作品较少”，也不以泛热点凑数。切换行业时，新任务使用对应行业配置；旧工作流保留创建时的配置快照。

每条作品保存标题、摘要、类型、来源 URL、来源平台、作者/账号（若可合法取得）、发现时间、原发布时间、封面/缩略图、产品类别、品牌/型号线索、内容形式、热度指标及采集时间、可访问状态与素材权利提示。热度按来源可得的播放、点赞、评论、分享、收藏等指标记录原值和时间窗；数据缺失时只标“热度待核实”，不显示虚构分数。按作品 ID、规范化 URL 和内容指纹去重；同款产品的不同作品各自保留。大厅展示作品级卡片与其热度依据，并支持品类、品牌、内容形式、平台、时间和热度筛选。过期或无法访问的作品可查看历史元数据，但发起创作前提示重新确认素材。

入选采用两道门槛：先满足当前行业相关性与种草/测评意图，再满足有来源证明的热度条件。热度阈值按平台和内容类型配置，优先使用同品类、同时间窗的分位数或相对排名，不把不同平台的原始播放量直接比较；首期阈值需用实际取得的数据样本校准。排序综合品类相关度、热度、互动质量、时效和与公司产品的可关联性，并展示各项依据。与公司产品不匹配的作品仍可留在大厅，但在产品匹配阶段允许用户无产品继续。

采集仅使用已获授权的 API、来源规则允许的公开数据或用户提供的素材；保存必要的来源与元数据。原图、原视频的存储和再利用应遵守来源授权，不把“可浏览”视为“可改编”。对仅提供榜单线索的来源，不自动宣称已取得完整作品内容；用户可打开原链接查看并在有权使用时补充素材。

### 5.2 分析 Agent 与产品推荐

产品库字段至少包含：名称、SKU/唯一 ID、品类、品牌、产品描述、核心卖点、适用场景、禁用宣称、标签、图片/视频素材及其使用授权、状态、可见人群、更新时间。停用或授权过期的产品不得推荐或用于生成。

推荐流程：先按权限、状态和素材授权过滤，再通过品类/场景/关键词召回候选，最后评分并解释。初版总分 0–100：主题及场景相关性 35、受众相关性 20、产品卖点适配 20、素材可用性 15、品牌及合规适配 10。分数是排序辅助，不是效果或合规保证。每条推荐展示匹配理由、关键不匹配点和分数，默认最多 10 条。

1. 第一轮展示 `≥65` 分且不超过 10 条。
2. 用户点击“没有合适产品”后展示 `≥60` 分的新增候选，并明确阈值已放宽；已看过的产品不重复。
3. 仍无合适产品时开放**授权范围内**的全部可用产品搜索、筛选与手选；不得绕过权限。
4. 用户可选择一个主产品，必要时添加少量辅产品；若无产品则按 4.1 的无产品路径继续。

阈值 65/60 是初始配置值，可由管理员调整，并在日志中记录生效版本。若候选为 0，直接显示“搜索授权产品”与“无产品继续”。产品选择确认后锁定产品快照；产品资料后来变更时，继续工作流前提示是否刷新快照。

### 5.3 文章 Agent 与局部编辑

输入为已确认的热点摘要、来源、创作目标及可选产品快照。一次生成三篇**完整、风格明显不同**的候选文章；默认风格可设为资讯解读、经验分享、轻量故事，用户可改写风格要求。每篇包含标题、导语、正文段落、图片占位及对应图片说明、产品植入位置、来源引用提示。纯文字路径不插入图片占位；带图路径按内容需要设置占位，不强制凑图。

编辑器以段落和句子为单位定位。用户选中范围后输入修改要求，文章 Agent 只能返回该范围的替换内容，并展示修改前后差异；用户接受后才写入正文。支持撤销、手工编辑、重新生成单篇以及从三篇中选一篇继续。局部修改不得暗改其他段落；跨段落一致性问题以提示形式交给用户确认。每次修改保存来源（AI/人工）、操作者、时间和版本。

### 5.4 美工 Agent

仅在文章有已确认图片占位时进入。使用已授权的产品图片、品牌素材及文章中每个占位的说明，先生成图片方案/提示，再生成或处理新图并回填到对应位置。每张图应保留来源素材、生成参数、用途位置和版本。用户可逐张接受、重做、替换、删除或上传自己的图片。产品外观、商标、包装细节不能被生成模型随意改写；必要时使用原始商品图与背景合成。用户完成整篇图文复核后进入审核。

### 5.5 编剧 Agent、分镜师 Agent 与视频生成

编剧 Agent 基于热点视频的可用信息（转写、镜头摘要、主题）及可选产品快照生成**新剧本**，而非逐镜复刻原视频。剧本结构包括目标受众、时长、核心信息、分场景台词/旁白、画面动作、产品出现方式和结尾引导。用户可对台词或场景局部描述修改，也可手工编辑；确认版本后进入分镜。

分镜师 Agent 将确认的剧本拆为镜头卡片：镜头编号、时长、景别、运镜方式、画面构图、主体动作、台词/字幕、音效/音乐意图、所需素材，并给出草图。用户可逐镜调整、增删、排序或局部重做；**首期确认后保存并下载剧本与分镜**。P1 才进入视频生成：按镜头产生画面/片段，再完成配音、字幕、音频和合成；展示预计耗时与资源消耗。失败的镜头可单独重试。成片支持预览、局部返工和导出，并保留字幕、封面及可编辑工程描述。视频涉及人物形象、声音或音乐时，只使用已授权资产。

### 5.6 审核 Agent 与最终确认

**首期 AI 内容审核由创作者按需触发，不作为保存或下载的前置门槛。**审核 Agent 检查敏感/违规用语、无依据的产品功效或绝对化宣称、品牌禁用词、版权与素材授权、个人信息、热点事实与来源一致性，以及图文/音视频中的文字。输出问题级别、具体位置、理由和修改建议；不能仅返回“通过/不通过”。审核结论为 `通过`、`需修改`、`需人工复核`。不确定的判断交给审核人员，不能宣称 AI 审核保证合规。

人工最终确认始终必需。审核后若修改了正文、图片、剧本、镜头或成片，原审核结论失效；系统显示“当前版本未审核”，用户可再次触发审核。成果与导出文件标记 `未审核`、`已审核通过` 或 `审核后已修改`，不得把未审核内容标为“审核通过”。产品/素材访问授权、文件安全和预算校验属于系统强制校验，不能通过跳过 AI 内容审核绕开。

### 5.7 聊天式工作流入口

聊天窗接受自然语言目标、链接和附件，并把用户意图转为可见的结构化任务卡：素材、内容类型、目标渠道、风格、时长/篇幅、产品选择与当前节点。聊天用于提问和下达局部修改指令；关键选择仍通过明确的卡片按钮确认。每条 Agent 回复附对应产物版本和操作入口，避免聊天记录成为唯一事实来源。支持从中途保存草稿、退出、恢复和查看节点时间线。

### 5.8 Agent 与模型配置

管理员可添加多个模型供应商连接，填写 API 地址、密钥、模型标识、能力类型（文本/视觉/图片/视频/语音）、超时、重试、并发和预算上限；保存前做连通性及能力测试。密钥加密存储，仅允许替换或删除，不回显明文。任务路由可指定主模型与备用模型；备用模型切换需记录，结果仍经过同样的确认和审核。

每个 Agent 的提示词支持草稿编辑、变量预览、测试运行、版本发布、回滚和权限控制。运行时固定模型配置版本、提示词版本、参数及输入快照。变量缺失或配置未通过测试时禁止发布。普通运营人员可查看获授权的配置说明，但不能读取密钥或改动全局提示词。

### 5.9 内容创作库与工作流日志

内容库按图文/视频、状态、产品、热点、创建者、时间检索。每个成果记录源热点、产品快照、成品版本、审核结论、可用素材与导出历史。图文至少支持 Markdown/HTML 与图片包导出；视频至少支持 MP4、字幕文件、封面和剧本/分镜导出。导出规格由目标渠道预设控制。

日志采用事件时间线，至少记录节点开始/结束、操作者、输入输出版本、模型与提示词版本、推荐阈值变化、人工选择、审核结果、错误与重试、用量/费用。日志不存明文密钥；对个人信息和敏感业务字段做最小化与权限控制。管理员可按工作流 ID 排查问题，运营可查看自己的记录。

## 6. 关键页面与交互验收

| 页面 | 必须完成的操作 | 成功反馈 |
| --- | --- | --- |
| 热点大厅 | 配置订阅、筛选热点、查看详情、发起创作 | 显示来源、时间、类型和采集状态 |
| 工作流入口 | 提交自带素材、查看分析、确认类型/产品、推进节点 | 当前节点、待用户动作、任务状态始终清晰 |
| 产品选择 | 查看前 10 条推荐、放宽阈值、搜索授权产品 | 推荐原因可解释；无权产品不可见 |
| 图文编辑 | 比较三稿、局部 AI 修改、手改、逐图确认 | 未选区域保持不变；可回看版本 |
| 视频编辑 | 审剧本、逐镜审分镜、预览与局部返工 | 每个镜头可定位、可重试 |
| 审核与成果 | 查看定位问题、修改、重审、保存/导出 | 最终稿和审核版本一致 |
| 设置与日志 | 测试模型、发布提示词、查执行记录 | 变更可回滚，错误可定位 |
| Agent 执行过程 | 逐 Agent 查看实时阶段、工具调用、依据、产物版本和修订 | 断线恢复后顺序不乱，记录与实际执行一致 |

## 7. 数据对象与系统组成

核心对象：`Tenant`、`User`、`Role`、`Product`、`ProductAsset`、`ProductGrant`、`HotspotSubscription`、`Hotspot`、`HotspotSource`、`Workflow`、`WorkflowStep`、`ArtifactVersion`、`AgentConfigVersion`、`ModelConnection`、`ReviewResult`、`AuditEvent`。热点与产品都保留不可变 ID；工作流引用其快照，避免后续源数据变化导致旧成果无法复现。

建议的服务划分：前端工作台；身份与权限服务；热点采集调度与队列；素材解析服务；工作流编排服务；Agent 运行层及模型适配器；产品检索与评分服务；媒体生成与存储；审核服务；日志与用量服务。长时间视频任务通过队列异步执行，节点结果持久化并使用幂等任务 ID，避免重试产生重复成片或重复扣费。

## 8. 非功能要求与风险控制

- **可用性**：采集和工作流分开运行；单个来源或模型故障不能使整个平台不可用。任务可重试、可取消、可恢复。
- **性能**：热点大厅常用筛选在正常数据量下目标 2 秒内返回；文本分析和推荐目标 30 秒内有结果或明确排队状态；图像/视频显示实时进度和预计耗时。具体 SLA 在模型与素材规模确定后压测定稿。
- **成本**：按用户/租户设定日用量和单任务预算；生成前显示预估，超额需有权限的人确认；记录实际花费。
- **安全**：传输加密、密钥加密、租户隔离、操作审计、素材访问签名和过期控制；上传文件做类型、大小及恶意内容检查。
- **质量**：模型输出使用结构化字段校验；不合格结果自动重试一次后交人工处理。生成事实性内容时标明依据，缺证据的产品宣称不得自动写入。
- **版权与平台规则**：保存原始来源、授权状态和使用范围；禁止无授权复制热点全文或直接搬运视频；外部平台发布前另行适配其现行规则。

## 9. 分期交付与验收标准

### P0：首期交付闭环

**已确认首期自建 Python 采集工具，采购数据源仅作为备选。**先接入已获权限的官方接口、来源规则允许自动访问的公开作品线索，以及用户手动提交的链接/素材；用可替换的来源适配器实现定时采集、失败重试、作品去重、行业与种草意图过滤、热度校验和热点大厅。抖音热门视频榜在权限获批后作为一个候选来源，不能承担全 3C 品类覆盖承诺。还包含类型分析、产品库与权限、65/60/全量搜索推荐、三稿文章与局部修改、图文占位及人工上传/生成图片、按需审核、成果库保存/下载、日志和基础模型配置。纯文字与带图图文都能从输入走到下载成果。

**视频首期做到剧本和分镜。**包含视频素材解析、剧本生成与局部修改、分镜卡片/草图与逐镜调整，支持保存和下载剧本及分镜；不把自动生成成片列为 P0 验收。系统应在分镜确认后显示“成片生成将在下一期开放”，不出现不可用的生成按钮。

**验收**：自建采集器至少完成一个经确认可自动访问的真实来源接入；自动推荐作品均有当前行业/品类、种草/测评意图和可追溯热度依据。来源未提供图文或视频时，大厅明确标识该类型暂靠手动导入，不伪称自动覆盖三平台。泛热点不进入推荐列表，候选不足时明确显示不足；来源故障可见且可重试。用一条纯文字热点、一条带图产品热点、一条自带链接分别完成图文流程；用一条视频热点完成剧本与分镜并下载；无权产品在推荐、搜索、详情和日志中均不可见；局部修改不会改变未选段落；断线后能从已确认节点继续；审核后的修改会使结论失效。**具体日量门槛在自建来源连续运行两周后，依据真实覆盖率确定。**

### P1：成片生成与运营增强

在首期已确认的剧本和分镜基础上，接入视频生成、合成、预览与局部重试；扩展多来源采集、热点聚合、提示词版本管理、主备模型和成本控制。

**验收**：一条有产品视频和一条无产品视频均能完成剧本→分镜→成片→审核→保存；单镜头失败可重试；成片版本与剧本、分镜、审核记录可追溯。

### P2：发布与效果优化

渠道授权、一键发布/定时发布、发布回执、失败重试、效果回收、推荐评分校准及团队审批。上线前逐平台验证账号权限、素材规格和合规要求。

## 10. 上线前需确认的业务参数

以下参数不阻塞 P0 方案设计，但需在实施前由业务方确定并写入配置：首批热点来源及授权方式；优先目标渠道和导出规格；产品库现有数据格式与权限划分；品牌禁用词和审核责任人；图片/视频素材授权范围；预期日采集量、日创作量及预算；数据保留期限。默认阈值 65/60、推荐上限 10 和三篇文章是初始产品规则，试运行后按真实使用数据调整。

## 12. 详细工作流状态与节点契约

### 12.1 通用节点规则

每个节点存储 `step_id`、`workflow_id`、`type`、`status`、`input_version_ids`、`output_version_ids`、`config_version_ids`、`started_at`、`finished_at`、`error_code`。节点状态只允许 `pending`、`running`、`waiting_user`、`succeeded`、`failed`、`cancelled`。工作流状态由节点推导，不能与节点事实冲突。

- 创建工作流时记录热点或上传素材的快照、创建者、租户和目标内容类型。
- AI 任务入队后立即返回任务 ID；重复提交相同节点与输入版本只创建一个任务。用户手动“重新生成”须产生新版本和新任务 ID。
- 进入 `waiting_user` 后不会自动推进。用户确认请求携带当前产物版本；旧页面提交旧版本时返回冲突并要求刷新。
- 修改已确认的上游节点时，下游产物标记 `stale`，不能再被当成当前成品或通过审核的版本。
- 失败保留已完成节点；重试从失败节点继续。连续失败达到配置上限时停止自动重试并显示人工处理入口。
- 取消后不再启动新任务；已运行的外部生成任务尽可能取消，不能取消时标明仍可能计费。

### 12.2 节点输入、输出与通过条件

| 节点 | 必要输入 | 结构化输出 | 人工通过条件 |
| --- | --- | --- | --- |
| 素材解析 | URL 或上传文件、来源信息 | 可读文本、图片清单、视频转写/关键帧、解析错误 | 素材可读；不全时用户补充 |
| 热点分析 | 解析版本 | 类型、摘要、产品线索、置信度、依据片段 | 低置信度或混合类型需确认 |
| 产品推荐 | 分析版本、授权产品集合 | 候选 ID、分数、维度分、理由、阈值轮次 | 用户选择产品或确认无产品 |
| 文章生成 | 热点快照、目标、产品快照 | 三篇结构化文章、图片占位 | 用户选定并确认一篇 |
| 图片制作 | 已确认文章、授权素材 | 每个占位的图片版本和来源 | 用户逐图及整篇确认 |
| 剧本生成 | 视频解析、目标、产品快照 | 场景、台词、时长、素材需求 | 用户确认剧本版本 |
| 分镜生成 | 已确认剧本、视频摘要 | 镜头卡片及草图 | 用户确认镜头序列 |
| 视频生成 | 已确认分镜、授权素材 | 分镜片段、合成成片、字幕、封面 | 用户确认成片版本 |
| 内容审核 | 最终产物、审核规则版本 | 问题清单、结论、扫描范围 | 通过或有权限的人复核通过 |

### 12.3 局部修改协议

局部修改请求必须携带 `artifact_version_id`、`target_unit_ids`、`selected_text_hash` 和用户指令。文章的单位是段落或句子，剧本是场景/台词，分镜是镜头/字段。返回 `replacement_units` 和修改说明，服务端校验目标之外的单位内容与顺序未变化；不通过则拒绝落库并提示重新生成。用户可先预览差异再接受或放弃。手工修改使用同一版本机制。全文重生成是单独动作，必须明确提示会产生新候选版本。

## 13. 数据与接口实施约定

### 13.1 主要数据字段

| 对象 | 必需字段与约束 |
| --- | --- |
| Product | `id, tenant_id, sku, name, category, description, claims, forbidden_claims, status, updated_at`；`tenant_id + sku` 唯一 |
| ProductGrant | `product_id, principal_type, principal_id, permission`；授权变更立即影响搜索和新任务 |
| Hotspot | `id, source_id, source_url, content_type, title, summary, published_at, discovered_at, fingerprint, access_status, rights_status` |
| Workflow | `id, tenant_id, creator_id, source_snapshot_id, target_type, current_step_id, status, created_at, updated_at` |
| ArtifactVersion | `id, workflow_id, kind, parent_version_id, content_uri_or_json, content_hash, author_type, created_at, stale`；版本不可覆盖 |
| ReviewResult | `artifact_version_id, rules_version, status, findings, reviewer_id, reviewed_at`；只对指定产物版本有效 |
| ModelConnection | `provider, model_id, capability, endpoint, encrypted_secret_ref, timeout, budget, status`；密钥不可明文读取 |

数据库主键均用不可推测 ID；每个业务查询都必须带租户过滤。大文件进对象存储，数据库保存元数据与访问引用。原始素材、处理后的中间文件和最终成品分别标记用途、授权与保留期限。

### 13.2 首期 API 能力清单

以下是接口能力而非强制 URL 命名；研发可按现有技术栈定 REST 或 GraphQL，但请求/响应语义必须覆盖：

1. 订阅增删改查、触发采集、热点分页检索与详情。
2. 素材上传或链接导入、解析状态查询、创建/查询/取消工作流。
3. 获取节点产物、确认类型、查询推荐、放宽阈值、授权产品搜索、确认产品。
4. 触发文章/图片/剧本/分镜/视频生成及任务状态查询。
5. 提交局部修改、比较版本、接受版本、确认节点、回退到历史版本。
6. 触发审核、获取定位问题、人工复核、保存成果和导出。
7. 产品及授权管理、模型连接测试、提示词测试/发布/回滚、日志查询。

所有写接口都校验身份、租户、对象权限与版本号；任务类接口使用幂等键。分页接口返回稳定游标。错误响应包含可展示的错误代码、可重试标记和追踪 ID，不向前端返回模型密钥或内部提示词全文。

## 14. 推荐评分的可实现定义

第一版采用可解释的规则评分，避免一开始将任意模型输出的“匹配度”当成客观分数。每个维度给 0–100 的子分，按第 5.2 节权重加权并四舍五入。品类/场景匹配可由标签和词项交集计算；受众、卖点和品牌适配可用经校验的结构化分析结果；素材可用性来自实际资产状态。缺失维度不得默认满分，记 0 并说明“资料不足”。禁用、无权限、授权过期、明确品牌冲突属于硬过滤，不参与评分。

排序规则：总分降序 → 场景分降序 → 产品最近更新时间降序 → 产品 ID 升序，保证翻页和重试稳定。首轮和第二轮返回的候选集合必须可复现，日志保存阈值、评分规则版本及候选 ID。管理员调阈值只影响新推荐任务；已确认工作流维持原候选快照。试运行时抽样由运营标注“合适/不合适”，再据此校准权重和阈值。

## 16. 失败、边界与空状态

| 场景 | 用户看到的处理方式 | 系统动作 |
| --- | --- | --- |
| 链接失效、需登录或禁止访问 | 提示上传素材或粘贴可读内容 | 保留来源和错误码，不编造摘要 |
| 内容类型判断不确定 | 展示依据并让用户选择 | 记录人工覆盖和新路由 |
| 无授权产品或无推荐结果 | 提供授权范围搜索、无产品继续 | 不扩大权限、不返回隐藏数量 |
| 模型超时/限流 | 展示排队或重试，允许取消 | 指数退避；达到上限停止 |
| 图片/视频任务部分失败 | 标出失败的占位或镜头 | 只重试失败单元，不覆盖成功单元 |
| 审核发现问题 | 定位到句子、图片或时间码，显示风险状态供用户修改 | 记录审核结论；首期不自动阻止下载 |
| 多标签页并发编辑 | 提示当前版本已更新 | 拒绝旧版本写入，保留本地草稿供比较 |
| 产品撤权或素材授权到期 | 提示重新选择或替换素材 | 阻止新生成与导出，旧版本标记不可用 |
| 成本预算不足 | 显示预计费用与所需授权 | 不启动生成任务 |

## 17. 可执行验收用例

每项用例应在测试环境使用固定样本、固定权限账号与可控模型响应执行；“成功”必须检查数据库状态和界面结果。

1. **纯文字路径**：导入纯文字热点 → 类型为纯文字 → 不出现产品和美工节点 → 生成三稿 → 选定、局部修改 → 保存并下载文字成果；另测用户主动触发审核及结果展示。
2. **带图且有产品**：导入带图热点 → 首轮仅见评分 ≥65 的最多 10 条授权产品 → 放宽后仅见新增的 ≥60 候选 → 搜索授权产品 → 确认产品 → 三稿、图片回填、保存和下载；审核按需触发。
3. **权限隔离**：给 A 用户授权产品 X、不给 B 授权。B 在推荐、搜索、详情链接、工作流上下文、导出和日志中都无法取得 X 的业务资料；直接调用接口返回无权限。
4. **局部修改**：选中一个段落并修改，比较修改前后所有非目标段落的内容哈希及顺序，必须完全一致；旧版本仍可查看。
5. **版本冲突**：两个页面打开同一文章，页面一保存新版本，页面二提交旧版本时被拒绝且不会覆盖页面一。
6. **审核失效**：审核通过后修改一张图片或一句正文，原结论不再显示为当前版本通过；导出文件标记“审核后已修改”，再次审核后更新状态。
7. **失败恢复**：生成中断或页面刷新后，工作流保留已确认节点；重试不生成重复节点或重复扣费记录。
8. **无产品视频**：用户确认无产品 → 剧本和分镜不能出现虚构的公司产品；若视频生成属于当前阶段，成片可追溯到确认的分镜版本。
9. **授权到期**：产品素材授权过期后，新的生成和正式导出被阻止，并提示替换素材。
10. **配置回滚**：发布新提示词后，新任务使用新版本；旧任务仍记原版本；回滚后下一任务使用回滚目标版本。
11. **过程可见性**：分别执行采集、分析、推荐、文章、美工、编剧、分镜和审核任务，页面均可查看阶段、依据、工具结果和产物版本；刷新或断线后继续显示完整事件；无权资料、密钥和未发生的工具调用不得显示。

## 18. 研发拆分与上线门槛

建议先建立可贯通的纵向切片，再扩展 Agent 能力：

1. 身份、租户、产品授权、文件上传和对象存储。
2. 工作流状态机、节点任务队列、版本系统和审计事件。
3. 手动热点导入、解析、分析及人工类型确认。
4. 产品过滤、评分、三档选择与快照。
5. 文章三稿、编辑器、局部修改协议和差异预览。
6. 图片占位、素材处理、最终复核、审核与导出。
7. 自建来源适配器、调度与采集监控；视频链路、模型配置增强按最终分期加入。

进入正式开发前：首批拟接入来源、允许的访问方式及可存储字段经过核实；抖音开放平台应用及热门视频榜接口权限的申请责任人明确；首批样本与产品数据已提供，素材授权已确认，原型及接口契约通过产品/研发/测试评审。进入试运行前：第 17 节 P0 适用用例通过，权限隔离和密钥保护通过检查，失败恢复及预算门槛可用。正式上线前：至少一个自建真实来源连续运行验证通过，业务方验收真实样本，明确数据保留与审核责任，建立采集失败、模型故障、费用超限的告警处理人。未获批的来源不得标为已交付；如自建来源覆盖不足，按第 24.2 节启动商业来源备选评估。

## 20. 热点采集的技术路线与平台选择

### 20.1 Python 采集器的定位

可以用 Python 编写各平台的采集适配器、定时任务、去重和入库逻辑；语言本身不能解决平台授权、接口配额和素材使用权。每个适配器统一实现 `fetch(since, cursor)`，输出 `source_id、source_item_id、title、summary、url、media_type、published_at、hot_metric、rights_status`，并写入采集批次、响应状态和上次成功时间。调度器负责限速、重试和告警。平台页面结构改变时只替换对应适配器，不改工作流主体。

首期自动采集的交付门槛是：目标平台、接口/授权、允许存储的数据范围和调用频率均明确；在测试环境连续运行并验证去重、漏采、接口故障与恢复。若平台权限尚未获批，可开发适配器和模拟数据，但**不能宣称该平台的自动采集已上线**。公开页面可用于发现热点线索的前提是其使用规则允许该采集方式；不以登录态抓取、绕过限制或复制全文/视频作为产品默认方案。

### 20.2 候选来源（2026-11-15 核对）

- **抖音热门视频榜**：官方文档提供热门视频榜接口，需申请 `data.external.billboard_hot_video` 权限；统计最近 24 小时，榜单数据每天 10 点前产出。文档未显示按 3C 品类或任意关键词检索作品的请求参数。因此它只能作为**全站热门视频候选池，再做 3C 与种草意图过滤**，不能承诺每天都有足量 3C 种草视频。来源：[抖音开放平台热门视频榜接口](https://open.douyin.com/platform/resource/docs/openapi/data-open-service/tops-data/hot-video-list/hot-video-list/)。
- **抖音关键词视频搜索**：官方能力只允许申请与自身业务紧密相关的关键词，不允许通用品类词或竞品品牌词，且仅返回最近 1 天的视频；需特殊权限及用户授权。它适合观察自有品牌/型号相关内容，**不能作为全网“3C 种草作品”通用搜索接口**。来源：[抖音视频搜索管理接入方案](https://open.douyin.com/platform/resource/docs/ability/search-management/video/)、[关键词视频搜索接口](https://open.douyin.com/platform/resource/docs/openapi/search-management/keywords-video-list/keywords-video/)。
- **百度热搜**：官方公开热点榜及规则页，称热点榜约每 5 分钟更新。适合作为通用话题线索；公开可见不等于提供可自由批量抓取或改编的授权，接入前需核验使用规则与可用接口。来源：[百度热搜榜规则](https://top.baidu.com/board?page=rule&tab=realtime)。
- **小红书**：其开放平台当前列出的开放 scope 只有基础用户信息，读取笔记为规划中；首期不把“自动读取全站笔记/热点”作为已具备的官方能力。来源：[小红书开放平台授权范围](https://openaccount.xiaohongshu.com/docs/scope)、[API 参考](https://openaccount.xiaohongshu.com/docs/api-reference)。

**已确认首期自建采集工具优先，商业作品数据源为备选。**研发以 Python 实现调度、来源适配器、规范化、行业过滤、热度校验、去重与告警；每个来源单独核实访问方式、字段与使用范围。抖音开放平台应用与权限仍从零申请：业务方指定企业主体和负责人，完成应用及 `data.external.billboard_hot_video` 权限申请；研发可并行使用模拟响应开发。官方榜单按日产出且为全站榜单，不能保证每天有足量当前行业作品。公众号和小红书的全站作品自动发现不能仅凭当前官方开放能力承诺。自建来源运行两周后评估覆盖缺口，再决定是否启动商业来源试采与采购。

## 21. 多平台通用与从零产品库的补充要求

首期内容目标选择“多平台通用”，因此先输出结构化主稿及通用文件包，不在生成时强行套用某个平台的口吻。**默认文章 800–1200 字；视频剧本 30–60 秒、9:16 画幅。**用户可在任务卡修改篇幅、图片比例、视频时长与画幅；管理员可调整默认预设。导出文件附带标题、正文/剧本、图片说明、素材来源、审核状态和版本号。P2 接入平台发布时，再为每个平台增加格式校验和派生版本，主稿不覆盖。

产品库从零建立，P0 必须增加产品单条录入、CSV 批量导入模板、图片批量上传、重复 SKU 检查、导入错误报告、产品分组、用户/角色授权、停用与授权到期设置。初始状态默认无产品授权；**平台管理员建立产品分组并授权，产品管理员维护资料**。批量导入只创建草稿产品，产品管理员检查资料、素材授权和禁用宣称后再发布为可推荐状态。至少准备“有完整资料”“缺图片”“已停用”“仅部分用户可见”四类样本进行验收。

## 23. 3C 产品规则、保留期与费用实施细则

### 23.1 3C 产品资料与可选审核规则

产品库增加 3C 常用字段：型号、规格参数、兼容设备/系统、接口与协议、电池及充电信息、保修与售后、认证或检测依据、官方产品链接、参数生效日期。字段按品类配置必填，不能要求所有 3C 产品填写不适用参数。每项可用于内容生成的参数或宣称应关联来源资料与版本；缺少依据时，文章和剧本不得把推测写成确定事实。

可选审核 Agent 在 3C 场景重点提示：型号与参数是否对应、兼容性条件是否遗漏、续航/充电等测试条件是否说明、价格或活动是否过期、绝对化或无依据的性能比较、产品图片是否与型号一致。审核规则由管理员维护；AI 给出定位和依据，创作者决定是否触发及如何处理。系统仍强制执行产品访问权限与素材授权校验。

### 23.2 数据保留

管理员可按租户设置保留天数，**默认 90 天**，适用于原始导入素材、解析中间文件、工作流日志及内容库成果；到期前在内容库与工作流中提示剩余时间，并允许有权限的用户下载备份。到期执行延迟删除队列，先将对象标为不可用，再删除存储文件及可识别业务数据；删除任务和结果保留最小化审计事件。受法律义务、争议保全或企业单独约定约束的数据由管理员设置例外策略并记录原因。默认值可调整，但变更要显示对现有数据的影响并写审计日志。

### 23.3 每日 AI 费用预算

管理员配置租户每日预算金额及可选用户级额度，按北京时间自然日重置。上线前必须填写具体金额和币种；未配置时禁止启动计费生成任务，只允许浏览、编辑和下载已有成果。每次生成前估算费用并预留额度，完成后按供应商实际计费回填，失败或取消时释放未消耗预留额度。达到预算上限时停止新任务，向管理员显示当日用量、待执行任务和调整入口；调整预算需审计。采集任务的外部接口成本也纳入单独的来源费用统计，避免与 AI 生成费用混淆。

## 24. 行业配置与来源验证

### 24.1 可切换行业配置

行业不写死在 Agent 提示词或数据库字段中。管理员可建立和发布 `IndustryProfile`：行业名称、层级品类树、品牌/型号词典、同义词与排除词、内容形式、热度筛选口径、产品资料字段模板、图片与视频素材要求、审核规则包和提示词变量。每个订阅与工作流引用配置版本。首次内置 **3C 全品类**配置；后续新增服装、美妆等行业时，通过配置和必要的专项审核规则上线，不影响旧工作流回放。

切换行业后，热点大厅默认展示该行业的作品，产品推荐只在用户有权访问且属于该行业或明确跨行业授权的产品中搜索。管理员可增删品类、调整同义词和排除词，并预览最近样本的命中/误判结果后发布。用户可选择整个行业，也可缩小到若干品类；“全品类”表示不人为限定预置的少数商品词，并不免除行业相关性判断。

服装可增加尺码、材质、季节等字段；美妆可增加成分、适用肤质、功效依据等字段。若未来进入医美等监管要求更高的行业，必须先建立对应资料、审核与资质规则，再开放该行业的自动创作和导出。首期不把 3C 审核规则直接套用到其他行业。

### 24.2 自建来源两周验证与商业备选触发

首期采用**自建采集工具连续验证两周**。每个来源先建立访问依据记录，列明官方 API 权限或公开页面允许的自动访问范围、调用频率、可保存字段、可展示范围和失效处理。不得以登录态模拟、绕过访问限制、批量复制全文/原图/原视频作为默认采集方式。用户自行提供且有权使用的素材由手动入口接入，与自动采集作品分开标记。

验证使用同一套 3C 全品类配置，按天记录：原始候选数、去重后数、3C 相关作品数、种草/测评作品数、同时有热度证据的合格作品数、图文/视频占比、品类覆盖数、可访问率、错误率、数据延迟和人工维护成本。随机抽样人工标注相关性、内容价值与可用性，计算准确率；记录漏掉的典型品类。热度指标必须注明来源与采集时间，不同平台分别评估。

两周后由业务方确认各渠道最低可接受日量、品类覆盖和质量门槛。若自建来源达不到目标，才启动第 25 节的商业数据源询价与试采；采购预算另行审批。商业备选须取得数据来源、授权链、缓存/展示/AI 分析用途、保留期限、调用额度与价格的书面说明。未接入的渠道在产品界面明确显示“暂不支持自动采集”，可继续使用手动导入，不能声称已覆盖微信公众号、抖音和小红书全平台。

### 24.3 来源适配器验收

每个来源必须提供独立健康页和采集批次记录。重复拉取同一时间窗不能产生重复作品；来源限流时按约定退避；授权失效时停止采集并通知管理员；字段缺失时保留原始响应标识和错误码，不编造热度。来源撤销授权后按合同范围停止展示和清理缓存。大厅中每个作品都能追溯到来源 ID、授权状态、原始链接、热度依据和过滤规则版本。

## 25. 商业数据源备选名单与验证问题

用户计划发布的主要渠道为**微信公众号、抖音、小红书**。以下名单仅在自建来源覆盖不足时启用。发布渠道与灵感采集渠道可以相同，但采购数据服务不等于取得这些平台的发布接口或第三方作品的改编权；发布能力应单独接入和验收。

1. **新榜 / 新榜有数（优先询价）**：官方资料展示公众号、抖音、小红书等平台的榜单与内容分析，并列有定制 API 服务。适合先询问能否一次采购覆盖三平台的**作品级**数据，而非只有账号榜。来源：[新榜榜单](https://www.newrank.cn/intro/ranklist)、[新榜开发者及定制服务](https://newrank.cn/account/api)。
2. **千瓜数据（小红书重点试采）**：官方页面列出热门笔记分析、商品种草榜、品类搜索、自定义品类等能力，适合检验图文/视频种草作品覆盖和跨行业品类配置。官网可查的是产品功能与会员额度，**未据此确认可供本平台调用的商用 API**，需商务书面确认。来源：[千瓜产品与价格](https://www.qian-gua.com/Home/AllPrice)、[自定义品类说明](https://wap.qian-gua.com/home/articledetail?id=3016)。
3. **飞瓜数据或蝉妈妈（抖音重点试采）**：飞瓜官方功能含热门素材、视频监控、品牌/商品分析；蝉妈妈官网展示热门视频库、带货视频库和图文带货榜。适合检验 3C 种草视频及其热度证据。**网页会员或导出功能不等于允许自动 API 接入**，需另行确认接口与授权。来源：[飞瓜功能说明](https://dy.feigua.cn/help/detail/9/447.html)、[蝉妈妈官网](https://www.chanmama.com/)。
4. **清博指数/清博管家（公众号候选补充）**：官方展示微信榜单的数据口径和全网文章精选，可试采公众号文章灵感；需确认是否提供作品级接口及可用于本平台的授权。公众号前台阅读数超过 10 万时可能仅显示“10W+”，不能当作精确数值排序。来源：[清博数据说明](https://www.gsdata.cn/site/data-open?show=wx%2Ctt%2Cdy%2Cks)、[清博管家](https://gj.gsdata.cn/)。

询价时统一要求供应商书面回答：① 三个平台分别提供哪些**作品级**字段、历史范围、更新频率和调用额度；② 能否按品类/关键词筛选图文和视频；③ 是否提供正式 API、沙箱、文档和 SLA；④ 是否允许在本产品内缓存元数据、展示封面/正文摘要、将作品用于 AI 分析与创作参考；⑤ 原文、图片和视频是否另需创作者授权；⑥ 删除、撤权、数据延迟和计费规则。如启动商业试采，沿用第 24.2 节的覆盖率与质量指标，不以供应商宣传的“全平台覆盖”代替实测。
